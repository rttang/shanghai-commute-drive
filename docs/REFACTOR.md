# 上海漫游：街景质量、独立驾驶与车轮交付记录

## 当前结论

本轮按用户“远处可以简化、街边近处使用实景图片，尤其地标”的反馈，接入 **17 个逐栋实拍参考模型**：外滩12栋、浦东5处。2026-09-09按新预算重建后，运行GLB合计 **16,136,044 字节（约16.14MB）**，保留原始图像尺寸、676,226个三角面及独立可编辑Blender工程。旧的整套10MB限制已经取消；普通模型按单个平均10MB控制，著名地标允许更大。用户批准修改驾驶和车轮，原42项冻结记录中仅4个源码/映射文件解冻，其余38项仍校验历史哈希。

这是一批有实际照片来源的外观重建。照片经过生成式透视与遮挡校正，结合窗洞、线脚、柱廊和建筑体积；**不是摄影测量，也没有把沿线全部建筑、隐藏立面和雕塑细节称作测绘级还原**。一般近处建筑和远处城市背景仍有简化。模型识别度改善不等于所有车辆和全城高保真已经通过用户验收。

## 街景方法与实景边界

用户已采纳任务“检查为何未调用 Subagent”的最后结论，本任务读取该任务后执行：保存当前画面和目标，独立制作街景，按驾驶、近看与全景三类机位比较，保留来源和可编辑工程，统一记录在本文。第一次共享窗格楼体虽然增加材质与线脚，仍未解决用户指出的雷同问题；该轮截图只保留为历史基线。

本轮处理顺序：

1. 从Commons文件页及官方API获取明确外景照片，保存摄影者、许可、拍摄日期、下载地址与SHA-256。先查看照片，再采用；没有只按文件名盲用。
2. 用内置image_gen进行单栋透视校正、去除路人树木等遮挡，生成独立立面。提示、照片映射和生成图哈希在 `.dream-loop/photo-prompts.json`。源照片与生成图分目录保存。
3. Blender按每栋图像的实际轮廓和门窗位置形成表面与实体。窗洞后退0.34米、柱廊为圆柱面、线脚突出、拱廊有深度，建筑主体沿背街方向延伸。和平饭店与南楼另有长侧立面；看不到的侧面标明推测。
4. 将建筑正面按米制临街边定位，剔除对应普通楼体。修正图像灰边造成的宽度缩水及背街剪切量；移除侧面重复共面墙，解决斜看闪纹。
5. 转为JPEG质量96并内嵌GLB，保留源图尺寸；Draco位置18位、法线14位、UV16位。预算按单个普通模型平均10MB，5个重点地标单独允许更大。构建前后检查当前车辆与驾驶文件快照，其余冻结文件继续校验历史哈希，避免街景生成覆盖汽车。本轮不重新生成或删除任何PNG。

## 车辆与驾驶（2026-09-09批准变更）

驾驶改动：

- 手动模式使用独立x/z位置、朝向与速度，以运动学自行车模型处理轴距和转角，最多每1/120秒积分一次。W/上为油门，S/下为刹车，A/D或左右为转向，空格急刹；松油门按滚动和空气阻力滑行，方向盘逐步转动并回正，速度较高时限制转角。
- 不再夹紧±2.4米横向偏移，也不把车辆每帧放回路线。路线投影仅用于进度和提示，手动距离可以后退；到达终点必须同时在终点附近。未转向会直行越出弯道，镜头和小地图跟随真实位置。
- 自动观光继续沿原两条路线。切换手动保持位置/朝向；回到车道附近并顺向行驶后才能交给自动观光，沿实际前进距离平滑接入。离路接管被拒绝，提示自行驶回或R重启。
- 车轮按累计行驶距离除轮胎半径滚动，停车后不继续自转；前轮内外轮使用不同转角，后轮不转向。交通车辆也有轮胎滚动和独立行进距离。暂停停止车辆与车轮，车辆切换不会沿用旧轮轴对象。

当前为二维运动学驾驶，不包含建筑/车辆碰撞、悬架、地形高程、倒挡和轮胎滑移；因此驶离道路仍可穿过简化场景物体。本轮没有把这些未实现项称作完整车辆模拟器。

## 回归与证据

2026-09-09整合后 `npm test` **22/22通过**，`npm run build` 通过。包含两条自动路线全程、手动20/30/60 FPS轨迹误差小于1厘米、弯道放手离路、停车不漂移、接管边界、车轮圆周滚动、前轮内外转角、资源来源和预算。

历史轮曾误把整套建筑预算定为10MB，把JPEG86降低到84；用户已明确纠正为单个平均10MB。本轮已修正预算与测试，恢复JPEG96及原图分辨率，原9,699,148字节版本另存备份；没有用增加空数据的方式填大模型。

固定截图采用同一路线、距离、视角、1280×720、DPR1、均衡档，暖机120帧后采样600帧。`photo-delivery-*` 是旧街景轮图像与JSON，并非本轮驾驶版本的最终验收；早期 `street-after-*` 的约60FPS属于旧通用场景，不能用来证明新版本性能。`photo-accepted-*` 只是早期文件名，不表示用户接受，已保留其38–50FPS样本。
