# 技术方案 / Technical design

本文描述当前私有项目采用的技术和实现，不代表已在所有设备验证。模块关系见[架构说明](ARCHITECTURE.zh-CN.md)。

## 技术栈

| 技术 | 当前版本／用途 | 选择与边界 |
| --- | --- | --- |
| TypeScript | 7.0.2，应用与测试 | 静态接口与模块组织；类型通过不等于运行资产正确 |
| Vite | 8.2.2，开发和静态构建 | 浏览器直接运行静态产物，无业务后端 |
| Three.js | 0.185.1，WebGL 场景 | GLTFLoader、材质、相机、光照、阴影和实例化 |
| meshoptimizer | 1.1.1，Meshopt 编解码 | 对匹配输入进行几何压缩；不等于早期有量化步骤的完整管线全部无损 |
| Draco | 模型加载器及部分源模型压缩 | 原转换有位置、法线和 UV 编码精度设置，保留原模型 |
| Blender + Python | 可编辑模型与离线处理 | 街区、家具、车辆、GLB 装配和工程打包；不参与浏览器运行 |
| Python 标准库 | 私有备份／恢复 | ZIP 内容去重、SHA-256、逐文件验证，无在线账号写进脚本 |
| Node 内置测试 | 回归与诊断 | 输入、暂停、动力学、碰撞、资源管理与场景数据 |

准确依赖版本以 `package-lock.json` 为准。npm 安装时按目标系统重建依赖，不能直接复用另一操作系统的 `node_modules`。

## 应用组织与数据

`src/main.ts` 组织启动和逐帧循环，`src/core` 负责输入与暂停，`src/tour` 划分驾驶、渲染、资源、车辆和活动。`public/tour-city.json` 保存地图与路线，`journey.json` 保存行程设计，碰撞和街景由各自清单输入。

当前 `vehicle-garage.ts` 读取 `docs/evidence/tourism/vehicle-dynamics-verification.json` 的游戏测量值。该文件作为必要运行输入保留在 Git 中。本次私有备份不改变这一既有实现；此前公开候选目录的数据移动不应用于当前版本。

## 驾驶、动力学与碰撞

- `Path` 对道路折线与高程采样，自动观光沿路线行驶；手动驾驶维护车辆位置、朝向、速度和转向。右侧车道偏移、路口和环线接缝分别有回归检查。
- 纵向动力学采用每车独立的加速曲线、踏板响应、阻力、制动和倒车参数；最大积分步长约 1/120 秒，过长帧间隔有上限。参数是游戏调校，厂家成绩只作为明确版本的参考。
- 碰撞使用多边形／低位轮廓、车辆外廓和垂直高度约束；隧道内外不能只按二维距离判断。修复路面时应同步核对可见几何与碰撞。
- 车轮使用四个独立枢轴，前轮根据转向角偏转，轮胎按行驶距离和轮径滚动。车辆切换前验证四轮结构，模型缓存同时限制保留数量。

## 建模和原始资料

OSM 提供道路、建筑轮廓和位置；照片、建筑资料与车型资料用于建模参考。Blender/Python 创建或加工建筑、道路、家具和车辆，保存可编辑工程，再导出 GLB。部分立面采用参考照片处理后的贴图，遮挡补全、未观察侧面和部分建筑尺寸属于推断。

照片、原模型、派生图、原作链接和许可记录分别保留。模型生成和压缩不会消除来源许可。完整总 GLB 用于离线校验及 Blender 总工程生成，当前网页按清单读取分块。

## 运行渲染与资源生命周期

- HDR 天空经 PMREM 用于环境反射；PBR 材质、阴影、窗灯、水面等在 `world.ts` 与材质模块中组织。
- 街景按位置和范围加载，使用不同加载／卸载半径避免边界反复装卸，并对前方分块预加载；当前 World 设置单路并发加载。
- 静态对象实例化与树木 LOD 降低重复绘制成本。卸载时按资源引用关系释放几何、材质、贴图和可关闭图像，避免释放仍被借用的资源。
- 部分 context／skyline 分块使用来源哈希匹配的性能派生版本，避免新源模型被旧优化文件替换。

## 发布压缩与既有托管方案

`build-release-assets.mjs` 从当前源清单选择模型，对道路环境继续空间分块，外置和复用贴图，并生成 Meshopt 压缩资源。资源 URL 带内容哈希。`build-release.mjs` 使用明确的运行文件清单生成 `dist-release`，按类型生成 gzip/Brotli 副本，并记录逐文件大小和哈希。

`serve-release.mjs` 提供静态预览、编码协商、缓存和条件请求。既有 Sites 适配把较大传输内容拆成可重组的 gzip 分片，由 Worker 返回正确内容类型和编码；该传输分片不同于 Three.js 可独立加载的空间 GLB。本次不更改已有站点。

当前开发清单有 47 个街景分块，保留的优化发布清单有 150 个。新建发布包应由当前源码和资源重建并验证，不能把历史数字视为每个未来版本的固定保证。

## 本地数据与隐私

偏好、行程和任务状态使用浏览器本地存储，相册使用 IndexedDB。主机名或端口变化会形成不同的浏览器源，Git 和资源恢复不会自动迁移浏览器进度。项目没有业务数据库服务或跨设备用户同步后端。

## 私有资源备份

当前有效 `public/`、源工程及必要原始素材按用途编组。相同 SHA-256 的内容只作为一个对象存入 ZIP，文件清单记录所有原路径。单附件控制在 GitHub 限制以内。

恢复脚本先验证附件和成员文件，不使用任意路径的批量解压；拒绝路径穿越、符号链接和内容不同的已有目标文件。完整性校验失败时保留原文件并报错。本次不把历史备份、失败导出、依赖缓存或重复构建目录再次打包。

## 验证层次

类型检查、源码回归、资源哈希、构建、浏览器交互和 Windows 实机是不同证据。`test:portable` 排除私人历史冻结档案检查，不代表该历史检查通过。恢复验收记录实际执行的命令、平台和失败，不把测试配置或 HTTP 200 当作完整运行验证。
